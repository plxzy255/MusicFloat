# Codex Surfaces Deep Dive - 2026-05-25

## Summary

MusicFloat should use repo-local agents as its next Codex layer, not a global MusicFloat skill or plugin yet. The app's hard problems are project-specific: bundle id `cv.MusicFloat`, Apple Music live workflows, provider order, profiling ledger rules, `reports/` update contracts, sandbox/entitlement policy, and MusicFloat's scripts. Those belong in `.codex/agents/*.md` and `.codex/environments/environment.toml` first.

Global skills are still useful, but only when a workflow is reusable across projects and not tied to MusicFloat's reports or scripts. A future `macos-codex-xcode-doctor` skill may qualify after it proves useful in MusicFloat, PlayStatus, and other macOS repos.

## 2026-05-25 Follow-up Implementation Status

Implemented from this deep dive:

- Repo-local agent specs exist under `.codex/agents/`.
- `script/agent_verify.sh` provides the repeatable handoff gate.
- `script/profile.sh doctor` provides a read-only MusicFloat doctor lane.
- `reports/report-index.md` routes durable agent findings.
- `script/generate_codex_environment.sh` owns the autogenerated Codex

## Surface Taxonomy

### Repo-Local Agents

Use for workflows that are project-specific and should be versioned with the repo.

Good MusicFloat fits:

- performance profiling with MusicFloat run IDs,
- live Apple Music lyrics forensics,
- privacy and entitlements review,
- release identity and signing checks,
- native panel/menu audit,
- translation memory/linkage gating,
- provider/cache boundary review,
- report curation.

Why:

- These agents cite MusicFloat files, scripts, bundle id, reports, and provider order.
- They should evolve with the repo.
- They can be reviewed in PRs.

Suggested location:

```text
.codex/agents/
  performance-profiler.md
  build-test-triage.md
  live-lyrics-forensics.md
  privacy-entitlements-reviewer.md
  translation-memory-gatekeeper.md
  native-panel-auditor.md
  release-identity-doctor.md
  provider-cache-boundary-auditor.md
  report-curator.md
  codex-xcode-doctor.md
  parser-fixture-curator.md
```

### Global Skills

Use for reusable workflows that should follow the user across repos.

Good current examples:

- `perp-research`: wraps local Perplexity MCP research and citation discipline.
- `media-link-inspect`: bundles deterministic media-probe scripts and source-resolution rules.
- `prompt-writing`: helps write/repair prompts once the runtime surface is known.

Possible future global skill:

- `macos-codex-xcode-doctor`
  - Only after the same workflow proves useful outside MusicFloat.
  - Should diagnose Xcode MCP, `xcrun mcpbridge`, `xctrace` cache access, Codex actions, and sandbox-vs-tool failures across macOS app repos.

Not recommended yet:

- `musicfloat-*` global skills.
  - Too repo-specific.
  - Would duplicate `.codex/agents` and drift from tracked reports.

### Plugins

Use only when a set of skills, MCP servers, apps, scripts, and marketplace metadata should be installed as a bundle.

MusicFloat does not need a plugin yet.

Reasons:

- No MusicFloat-specific MCP server exists.
- No custom UI app/connector is needed.
- The next layer is text contracts plus existing scripts.
- A plugin would add install/marketplace overhead without solving the immediate agent workflow gap.

When a plugin might make sense:

- If MusicFloat gains a reusable MCP server exposing structured run ledger, trace summaries, version status, and live log summaries.
- If multiple macOS music projects share the same diagnostics toolkit.
- If the user wants a personal marketplace entry for a cross-repo macOS app doctor bundle.

### Prompts

Use for one-off role steering or broad non-project-specific behavior.

Current prompt inventory is useful, but too generic for MusicFloat-specific correctness:

- `performance-reviewer` understands generic performance hotspots.
- `security-reviewer` understands generic OWASP/security review.
- `debugger` understands root-cause debugging.
- `verifier` understands evidence-backed completion.

MusicFloat should not rely only on these prompts for:

- live Apple Music proof,
- raw lyric/listening privacy,
- MusicFloat report update rules,
- valid run ID checks,
- `--drive-music` playback side effects,
- sandbox/hardened-runtime product policy.

### Actions

Use for common local commands the user or agent should be able to run without remembering flags.

Current:

```toml
[[actions]]
name = "Run"
icon = "run"
command = "./script/build_and_run.sh"
```

Recommended safe actions:

```toml
[[actions]]
name = "Verify App"
icon = "check"
command = "./script/build_and_run.sh --verify"

[[actions]]
name = "Test"
icon = "test"
command = "xcodebuild test -project MusicFloat.xcodeproj -scheme MusicFloat -destination 'platform=macOS' -derivedDataPath .codex/DerivedData"

[[actions]]
name = "Profile Report"
icon = "list"
command = "./script/profile.sh report"

[[actions]]
name = "Profile Disk"
icon = "storage"
command = "./script/profile.sh disk"

[[actions]]
name = "Release Status"
icon = "info"
command = "script/release_self.sh --status"
```

Actions to avoid as one-click defaults:

- `./script/profile.sh clean`
  - Destructive cleanup.

- `./script/profile.sh sample ... --drive-music`
  - Changes active Music.app playback.

- `script/release_self.sh --install`
  - Replaces installed app.

- Long-running telemetry/log streams.
  - Useful, but should be an explicit task with a stop condition.

### MCP And Xcode

Use Xcode MCP as the interactive Xcode state lens:

- current workspace tab,
- build logs,
- issue navigator state,
- test discovery,
- running Xcode context.

Use shell/scripts as the canonical reproducible project gates:

- `./script/build_and_run.sh --verify`,
- `xcodebuild test ...`,
- `./script/profile.sh report`,
- `./script/profile.sh disk`,
- `script/release_self.sh --status`.

Rule:

- If Xcode UI state and shell output conflict, report both and prefer fresh reproducible shell output for final gates.
- Use Xcode MCP for faster diagnosis and stale-warning detection.

## Repo-Local Versus Global Decision Matrix

Use repo-local agent when:

- It mentions `cv.MusicFloat`.
- It depends on `reports/performance-runs.jsonl`, `reports/performance-flaws.md`, or `reports/lyrics-accuracy-status.md`.
- It depends on MusicFloat provider order.
- It depends on `script/profile.sh`, `script/build_and_run.sh`, `script/release_self.sh`, or `script/version.sh`.
- It changes with the codebase.
- It should be reviewed in PRs.

Use global skill when:

- The workflow is useful across multiple repos.
- It bundles scripts/references that are not project-specific.
- It has stable trigger wording.
- It can validate with `skill-creator` quick validation.
- It does not need MusicFloat's internal reports to be correct.

Use plugin when:

- The workflow needs installable bundle metadata.
- It contains one or more skills plus tools/MCP/apps.
- The user wants it in a marketplace.
- It needs the plugin creator's cachebuster/reinstall workflow.

Use prompt when:

- The task is a one-off role style.
- The workflow is not stable enough to become a skill/agent.
- The prompt does not need bundled scripts/references.

Use action when:

- The command is common,
- low-risk,
- bounded,
- understandable from its name,
- and safe enough for a one-click UI control.

## Recommended Implementation Order

1. Add repo-local agent specs.
   - Start with privacy/entitlements, live lyrics, translation memory, release identity, native panel, provider/cache, build/test triage, report curator, and Codex/Xcode doctor.

2. Add safe Codex actions.
   - Follow-up status: implemented through
     `script/generate_codex_environment.sh`.
   - Keep destructive cleanup, release install, and Music.app-driving profile
     paths out of one-click actions.

3. Add `reports/report-index.md`.
   - Clarify which reports agents update.

4. Add `script/agent_verify.sh` or equivalent.
   - One command for handoff gates.

5. Add a read-only `doctor` command.
   - Follow-up status: implemented as `./script/profile.sh doctor`.
   - It diagnoses environment, Xcode MCP, profiling dependencies, bundle
     identity, artifact sizes, Codex actions, and live preflight state without
     recording or driving Music.app.

6. Only then consider global skills.
   - Promote `codex-xcode-doctor` if it works across multiple macOS repos.

## Anti-Patterns

- Do not build a MusicFloat plugin before the repo-local agent/action layer exists.
- Do not make one giant "MusicFloat mega-agent"; use narrow specs that map to risk zones.
- Do not turn the performance profiler into the owner of privacy, live-lyrics correctness, or release identity.
- Do not make global skills that cite repo-local report paths.
- Do not put `--drive-music`, `profile.sh clean`, or release install commands behind casual one-click actions.
- Do not let prompt wording carry durable project policy that belongs in tracked `.codex/agents` or `AGENTS.md`.
