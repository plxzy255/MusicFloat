# Skills, Plugins, Fixtures, And Developer Lanes Strategy - 2026-05-25

## Summary

MusicFloat's next Codex work should not start by creating a plugin or global skill. It should start with repo-local agent specs, safe Codex actions, a report index, and eventually a small agent verification script. The reusable parts can later graduate into global skills if they prove valuable outside MusicFloat.

The strongest external developer-workflow reference in `.tmp` is `applemusic-like-lyrics`, because it has named lanes, parser fixture breadth, and CI discipline. PlayStatus is useful for native app patterns and cache behavior, but it is not a strong Codex workflow reference.

## 2026-05-25 Follow-up Implementation Status

Implemented from this strategy:

- The repo-local `.codex/agents/` set now exists, including the proposed
  `musicfloat-agent-check.md` spec.
- `script/agent_verify.sh` now implements the boring, predictable full handoff
  gate described below.
- `reports/report-index.md` now gives agents durable report routing.
- `script/generate_codex_environment.sh` now owns the autogenerated Codex
  environment file and generates the safe Run/Verify/Test/Doctor/Profile/Release
  actions.
- `script/profile.sh doctor` now implements the read-only doctor lane for Xcode,
  `mcpbridge`, bundle identity, artifact size, Codex actions, and live preflight
  checks.

  transient catalog failures, and in-flight lookup joining.

  fractional timestamps, and repeated timestamp ordering.

Still future:

- A general global skill or plugin. The MusicFloat workflows are still
  repo-specific enough to keep local.
- Broader fixture-file corpus work for TTML edge cases and localization metadata
  beyond the targeted parser/provider tests added in this pass.

## What Skill-Creator Guidance Implies

The local `skill-creator` guidance says effective skills should be:

- concise,
- modular,
- triggered by clear metadata,
- supported by optional `references/`, `scripts/`, and `assets/`,
- validated with `quick_validate.py`,
- optionally exposed with `agents/openai.yaml`.

Implication for MusicFloat:

- Most current needs are too repo-specific for global skills.
- They should live as `.codex/agents/*.md` first.
- If a workflow later becomes reusable, convert it into a global skill with:
  - `SKILL.md`,
  - optional `references/`,
  - optional deterministic scripts,
  - `agents/openai.yaml`,
  - `quick_validate.py` validation.

## What Plugin-Creator Guidance Implies

The local `plugin-creator` guidance is for installable plugin bundles with:

- `.codex-plugin/plugin.json`,
- optional skills/hooks/scripts/assets/MCP/apps,
- marketplace entries,
- cachebuster/reinstall flow.

Implication for MusicFloat:

- Do not create a MusicFloat plugin yet.
- There is no MusicFloat MCP server or cross-repo plugin surface to package.
- A plugin would add install/update overhead before the workflow is stable.

Possible future plugin:

- `macos-app-doctor`
  - Skills: Xcode doctor, signing/entitlements doctor, release identity doctor.
  - Scripts: read-only bundle/signing/version probes.
  - MCP: optional Xcode helper if needed.
  - Scope: multiple macOS app repos, not just MusicFloat.

## Named Developer Lanes

Borrow from `applemusic-like-lyrics`:

- named build/test/lint/release lanes,
- CI-friendly lane names,
- parser fixture/test separation.

Do not borrow:

- Nx/pnpm monorepo complexity,
- browser rendering architecture,
- web-player DOM assumptions.

Recommended MusicFloat lanes:

```text
Verify App       -> ./script/build_and_run.sh --verify
Test             -> xcodebuild test -project MusicFloat.xcodeproj -scheme MusicFloat -destination 'platform=macOS' -derivedDataPath .codex/DerivedData
Profile Report   -> ./script/profile.sh report
Profile Disk     -> ./script/profile.sh disk
Release Status   -> script/release_self.sh --status
Live Preflight   -> ./script/profile.sh preflight-live
```

Avoid default one-click lanes for:

- clean,
- install,
- live drive,
- long-running telemetry.

## Agent Check Script Strategy

Implemented script:

```text
script/agent_verify.sh
```

Purpose:

- one consistent handoff gate for normal code changes.

Implemented behavior:

1. Print branch, commit, dirty state.
2. Run the full Xcode test suite.
3. Scrape compiler output for warnings.
4. Run app verify.
5. Show profile report summary.
6. Show profile disk summary.
7. Avoid live driven profiling unless explicitly requested.

Design constraints:

- It should be boring and predictable.
- It should not clean artifacts.
- It should not install the app.
- It should clearly label any command that launches MusicFloat.
- It should not mutate Music.app playback.

## Doctor Script Strategy

Implemented script:

```text
./script/profile.sh doctor
```

Read-only checks:

- Xcode path/version.
- `xcrun --find mcpbridge`.
- `xcrun xctrace list templates` availability and cache-access failure explanation.
- `.codex/traces` size.
- DerivedData size.
- current bundle/version status.
- configured Codex actions.
- Music.app live preflight readiness without driving playback.
- git dirty state.

Must not:

- delete traces,
- run Instruments recording,
- launch/drive Music.app,
- install Release app,
- request broad escalation without naming the exact blocked check.

## Parser Fixture Strategy

Current state:

- MusicFloat has useful inline parser tests for TTML timing, spacing, language metadata, CJK, Arabic, Russian, punctuation, and parentheticals.
- Reference `applemusic-like-lyrics` has broader parser corpus dimensions.

Recommended direction:

- Add MusicFloat-owned fixtures, not copied third-party lyrics.
- Keep fixture text synthetic or public-safe.
- Separate parser fixtures from live provider payloads.
- Add round-trip and malformed-input tests where useful.

Fixture dimensions to add over time:

- TTML localizations,
- sidecar metadata,
- romanization/transliteration fields,
- ruby annotations,
- duet/background wrappers,
- line timing versus word/syllable timing,
- CRLF handling,
- invalid timestamp handling,
- repeated timestamps,
- parse/stringify stability,
- storefront/language selection fixtures.

Agent owner:

- `parser-fixture-curator.md`

Report owner:

- `reports/lyrics-accuracy-status.md`
- future parser fixture plan if this grows.

## Cache Doctor Strategy

Borrow from PlayStatus:

- byte caps,
- entry caps,
- TTLs by object kind,
- shorter unavailable-lyrics TTL,
- inflight de-dupe,
- usage text,
- clear-cache affordance.

Avoid from references:

- Manzana's single pickle cache without TTL/cap/corruption/privacy boundaries.

MusicFloat cache doctor should be read-only first:

```sh
./script/profile.sh disk
rg -n "MediaCache|memoryCache|cache|inflight|timeout" MusicFloat reports
```

Future cache usage report should include:

- memory entries,
- disk bytes,
- oldest/newest entry,
- unavailable/miss entries,
- cache version,
- privacy note,
- clear-cache action only when user requests it.

2026-05-25 follow-up: Settings now exposes a compact cache usage string and a
Clear Cache button for the opt-in disk cache path. A future cache doctor should
stay read-only unless it is explicitly asked to clear cache state.


Purpose:

- Translation architecture -> `reports/translation-architecture-plan.md`
- Runtime bugs/timeouts -> `reports/bugs-and-issues.md`
- Research-only audits -> dated `reports/research-YYYY-MM-DD-*.md`

Rules:

- Do not cite temp run IDs as durable evidence unless labeled local-only.
- Do not commit raw traces.
- Do not paste raw listening data.
- Update trackers when evidence invalidates prior claims.

## Skill Validation Workflow If Promoted

If any workflow becomes a global skill:

1. Create with `skill-creator` conventions.
2. Use lowercase hyphen-case name under 64 characters.
3. Keep `SKILL.md` concise.
4. Put long details in `references/`.
5. Put deterministic commands in `scripts/`.
6. Generate `agents/openai.yaml`.
7. Validate:

```sh
python3 /Users/psp/.codex/skills/.system/skill-creator/scripts/quick_validate.py <skill-dir>
```

Suggested `agents/openai.yaml` pattern:

```yaml
interface:
  display_name: "MacOS Codex Xcode Doctor"
  short_description: "Diagnose Codex and Xcode app workflows"
  default_prompt: "Use $macos-codex-xcode-doctor to inspect local Xcode MCP, build, profiling, and bundle identity affordances."
```
